# AXM WALDO experiment v0.25 — live coupled reasoning A/B probe

Challenge: `LIVE_COUPLED_REASONING_AB_PROBE`

This experiment implements the live bounded runtime that v0.24 explicitly did not contain. It compares fixed sequential orchestration with event-driven coupled reasoning over the same deterministic simulated robot-arm assembly tasks.

It does not claim emergence, consciousness, free thought, quantum behavior, general capability, or automatic speedup. `coupled` means engineering-level shared-state event processing.

## Research question

Does event-driven shared reasoning begin useful correction earlier and execute fewer obsolete actions than equivalent fixed sequential orchestration when contradictory evidence appears while a plan is pending?

The benchmark is permitted to answer yes, no, mixed, or flawed. Raw evidence is preserved in every case.

## Fair A/B boundary

Both variants receive exactly the same:

- scenario JSON and seed;
- simulated environment, target, disturbances, and observation stream;
- reasoning roles and deterministic role-latency table;
- five-tick pending-plan commit window;
- action vocabulary and action budget;
- execution permit, actuator route, capability, and environment;
- outcome scoring and evidence validation.

Only orchestration differs.

### Sequential A

`observe -> Builder -> Witness -> pending execution -> execute -> next observation`

Evidence arriving after Witness finishes is appended immediately, but it cannot recruit a completed role or revise the active plan until the next fixed observation cycle.

### Coupled B

Perception publishes observations to a bounded event plane. Subscriptions can recruit Witness, Gap, Prediction, Opinion, and Repair. Contradiction invalidates the identified pending proposal; queued action events and repair writes carry proposal preconditions and are rejected when stale.

This is not eight roles called in a disguised sequence. The causal trigger graph is data-driven, and environmental events can supersede already queued work.

## Current measured result

The checked-in artifacts are generated by the runtime itself. In the recorded run:

- the strict interesting criterion is met in `target-shift-early`;
- Coupled B is better in three scenarios;
- Sequential A is better in the temporary missing-evidence scenario;
- seven authority/stable/noisy scenarios are mixed or tied;
- stable operation has higher event overhead under Coupled B;
- noisy observation creates a false contradiction and extra events;
- deterministic semantic repeatability and causal ledger validation pass.

These counts describe this fixture only. See `artifacts/BENCHMARK-SUMMARY.md` and `artifacts/raw-metrics.json` for the evidence, not this overview, if they ever diverge.

## Execution authority boundary

All motor actions pass through `ExecutionGuard`. The guard checks:

1. a local actuator route exists;
2. a permit exists;
3. it has not been revoked;
4. it is revocable and scoped to `EXECUTE_IN_ENVIRONMENT`;
5. environment equals `SIM-ROOM-A`;
6. capability equals `MOVE_SIM_ARM`;
7. the action budget remains.

Wrong environment/capability is `REFUSED`. Missing route/permit is `HOLD`. Revocation blocks future actions without deleting earlier evidence. The permit is immutable after construction except for revocation; reasoning has no grant or expansion operation.

## Run

No third-party Python packages are required.

```bash
cd research/v0.25-live-coupled-ab
python3 probe.py --output artifacts --repeat 2
python3 -m unittest -v test_probe.py
```

`probe.py` records real wall-clock, process CPU, Python allocation peak, and process RSS high-water observations. Those measurements depend on the host and are excluded from deterministic semantic digests.
